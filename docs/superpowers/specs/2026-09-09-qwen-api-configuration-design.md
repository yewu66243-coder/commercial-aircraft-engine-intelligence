# 千问 API 配置与运行设计

## 目标

将用户提供的已配置环境文件安全地安装到项目根目录，使现有工作台能够在保留 DeepSeek 默认选项的同时，从界面手动选择千问生成模型，并启动本地服务完成运行验证。

## 方案

采用完整环境文件安装方案：将用户提供的 `.env` 原样复制到项目根目录。项目已有 `.gitignore` 规则排除 `.env`，因此凭据不会进入版本控制。配置内容及测试输出不得回显 API 密钥。

不修改现有模型选择代码或前端默认值。现有实现已经提供 DeepSeek 与千问两个模型选项，并以 DeepSeek 为默认；千问运行时读取 `DASHSCOPE_API_KEY`、`QWEN_BASE_URL`、`QWEN_MODEL`、`QWEN_FAST_MODEL` 和 `QWEN_STRATEGIC_MODEL`。

## 数据流

1. 应用启动时通过 `python-dotenv` 加载项目根目录的 `.env`。
2. `/api/model-providers` 根据环境变量返回不含凭据的模型可用性元数据。
3. 用户在界面选择千问后，请求携带 `llm_provider: "qwen"`。
4. 后端为该请求构造独立的千问运行时，将配置的端点、模型名和密钥传给 OpenAI 兼容客户端，不修改进程级 DeepSeek 配置。

## 错误处理与安全

- 在复制前确认源文件存在，目标路径严格限定为项目根目录 `.env`。
- 不打印、记录或提交 API 密钥；验证信息只显示配置是否存在以及非敏感模型元数据。
- 如果千问连通性验证失败，保留配置文件，报告 HTTP 状态或去敏后的错误摘要，不将失败误报为可用。
- 如果端口 8000 已被占用，先识别占用进程；仅复用确认属于本项目的健康服务，不终止无关进程。

## 验证与运行

1. 运行现有模型选择测试，确认双模型目录、千问请求级配置和凭据保护行为。
2. 使用配置的千问端点和模型执行一次最小聊天请求，确认凭据、模型名和兼容接口可用。
3. 使用项目现有启动方式启动本地服务。
4. 请求根页面和 `/api/model-providers`；确认根页面可访问、目录默认项为 `deepseek`，且 `qwen.configured` 为 `true`。
5. 保持服务运行，供用户在界面中手动切换千问并发起任务。

## 非目标

- 不把千问设为默认模型。
- 不改动已有模型选择界面和生成流程。
- 不提交 `.env`，不轮换或修改用户提供的凭据。
- 不执行完整情报报告作为启动验证，避免不必要的 API 与检索消耗。

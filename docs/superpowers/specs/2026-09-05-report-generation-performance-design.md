# 报告生成性能优化设计

## 目标

在保留论文式报告结构、来源核验、图片处理和 Markdown、Word、PDF 导出的前提下，将常规商用航空发动机情报报告的目标生成时间控制在 15～30 分钟。复杂任务允许超过 30 分钟，但不再因低收益的重复全篇复查持续执行最多 11 轮。

## 采用方案

系统采用“最多三轮、风险驱动、停滞提前结束”的平衡策略：

1. 第一轮继续进行全篇编辑和逐段来源复查，建立完整问题清单。
2. 第二、三轮只修订并复查上一轮有问题的段落，以及修订可能影响的相邻段落。
3. 一旦全部硬性质量检查通过，立即结束校订。
4. 连续两轮的有效问题数没有下降，或本轮未产生有效文本变更时，提前结束并选择所有已严格复查版本中问题最少的一版。
5. 三轮结束后仍有问题时，如实返回 `needs_review`，把具体问题保存在后台研究记录，不把内部核验标记写入正文。

## 质量边界

以下检查始终执行，不受提前停止影响：

- 报告基本结构、摘要、关键词、章节、表格、图片和参考文献检查。
- 正文引用与本轮实际取得原文的对应检查。
- 数字、单位、型号、时间和计划/实际属性的证据检查。
- Markdown、Word、PDF 使用同一份最终正文。
- 正文普通字重、图题与图源居中、内部核验标记不进入正文。

提前停止只减少低收益的重复模型调用，不降低通过条件。未通过的报告必须保持 `needs_review`，不得伪报为完成。

## 实现边界

`backend/reporting/finalization.py` 负责轮次上限、局部复查和提前停止决策。`three_agent_service.py` 负责传入平衡模式配置、记录各阶段耗时，并把当前阶段、轮次和预计剩余范围返回给前端。前端展示真实任务耗时和阶段进度；连接探测次数继续作为诊断信息，但不再被误认为生成进度。

默认平衡模式最多三轮。实现保留显式配置入口，便于以后增加快速模式（最多两轮）和严格模式（最多五轮），但本次不增加新的用户选择控件。

## 数据流

检索和初稿完成后，系统执行第一轮全篇校订与严格复查。每轮将问题按段落定位，下一轮只向模型发送待修订段落、必要的相邻上下文和对应证据片段。每轮结束保存报告快照、有效问题数、文本是否变化、耗时和停止原因。最终选择硬性问题最少、严格复查完成且内容合同未回归的版本导出。

## 异常处理

单次模型调用沿用现有超时和重试策略。某一轮超时或返回无效结果时，保存最近一次完成严格复查的版本并返回 `needs_review`。局部修订无法唯一定位时，不执行可能误改正文的替换，并把该问题留在后台记录。导出失败继续单独报告，不把已经完成的研究结果丢弃。

## 验收标准

- 默认新任务最多执行三轮校订。
- 质量全部通过时立即停止。
- 连续两轮问题不下降或没有有效文本变化时提前停止。
- 后续轮次不再重复复查全部无问题段落。
- 最终选择问题最少的已复查版本，失败状态保持真实。
- 原有 101 项报告测试继续通过，并增加轮次上限、停滞停止、局部复查范围和最佳版本选择测试。
- 使用固定验收资料完成一次生产服务复验，目标耗时 15～30 分钟；若外部模型延迟导致超时，记录各阶段耗时并确认系统自身未超过三轮。

## 当前任务处理

设计和后续代码改动不终止当前正在生成的报告。当前任务由已加载的旧代码继续执行，新的平衡策略从服务更新后的下一次任务开始生效。

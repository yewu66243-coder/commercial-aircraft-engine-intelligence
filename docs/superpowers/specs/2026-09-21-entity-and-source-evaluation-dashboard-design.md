# 核心技术实体与公开溯源链接测评功能设计

## 背景与目标

现有报告流水线已经能够从“核心实体与参数清单”中抽取实体、检查实体是否具备证据，并检查报告中的 URL 是否可访问或支撑相邻结论。这些结果目前主要保存在运行记录中：实体金标准匹配只按名称进行粗粒度判断，前端也没有面向用户的测评面板。

本功能在现有报告生成链路上增加确定性、可复现的测评能力。每次报告生成完成后，系统自动计算：

1. 机构、型号、材料、参数、时间及其他核心技术实体的 Precision、Recall 和 F1；
2. 报告实际引用的公开 HTTP/HTTPS 链接可访问率；
3. 固定阈值下的达标状态，并在报告顶部展示测评摘要和分类明细。

实体严格准确率只在存在任务对应的金标准文件时计算。没有金标准时，系统展示现有自动证据支撑率作为代理指标，并明确说明它不能替代准确率。测评失败不得阻止报告导出。

## 范围

### 包含

- 扩展现有实体测评器，增加类别归一、别名匹配、参数数值与单位匹配、分类指标和综合指标；
- 复用现有报告 URL 可访问性检查，不引入 URL 内容支撑度或来源权威性评分；
- 在报告接口的 `run_statistics` 中提供统一的 `evaluation_summary`；
- 在报告预览顶部增加自动测评面板；
- 将完整测评结果写入现有运行记录；
- 为算法、接口接线和前端渲染增加自动测试。

### 不包含

- 独立测评中心、报告上传复测或批量对比；
- 在网页中上传或编辑金标准；
- 使用大模型判断实体是否匹配；
- 判断公开链接内容是否支撑报告结论；
- 评价链接来源的权威性；
- 展示逐条正确、误抽和漏抽实体明细。

## 用户流程

1. 维护者在 `outputs/records/entity_ground_truths/` 中放置与任务名称对应的 JSON 文件。
2. 用户按现有流程生成报告，无需增加开关或填写额外配置。
3. 报告写作和校订结束后，系统对导出前最终正文执行实体测评和 URL 可访问性检查。
4. 报告仍按现有流程导出为 Markdown、Word 和 PDF。
5. 前端收到结果后，在报告质量状态下方显示三张核心指标卡；用户可展开分类指标表格。
6. 完整结果随本次运行记录持久化，便于后续审计。

## 金标准文件

### 位置和匹配规则

继续使用现有目录：

```text
outputs/records/entity_ground_truths/
```

候选文件解析沿用当前任务安全名称规则，依次查找任务同名 JSON、任务安全名称 JSON 和目录中的 `ground_truth.json`。使用通用 `ground_truth.json` 时，文件中的 `task` 必须与当前任务匹配；避免一个任务误用另一个任务的标准答案。

### JSON 结构

```json
{
  "task": "任务名称",
  "entities": [
    {
      "type": "机构",
      "name": "Pratt & Whitney",
      "aliases": ["普惠", "P&W"]
    },
    {
      "type": "材料",
      "name": "粉末金属"
    },
    {
      "type": "参数",
      "name": "起飞推力",
      "value": 33110,
      "unit": "lbf",
      "tolerance": 0.01
    }
  ]
}
```

字段规则：

- `task`：可选字符串；存在时必须与当前任务一致；
- `entities`：必填数组；
- `type`：必填字符串，可使用下文定义的类别别名；
- `name`：必填字符串；
- `aliases`：可选字符串数组；
- `value`：参数类可选数字或可解析的数字字符串；
- `unit`：参数类可选字符串；
- `tolerance`：参数类可选非负小数，表示允许的相对误差；未提供时使用 `0.01`，即 ±1%。

文件不存在与文件无效是两个不同状态。文件不存在时允许代理测评；文件存在但无法解析或不符合结构时返回明确的 `invalid_ground_truth` 状态。

## 实体归一与匹配

### 类别归一

实体类别统一为以下稳定标识：

| 稳定标识 | 中文显示名 | 可接受别名示例 |
| --- | --- | --- |
| `organization` | 机构 | 机构、企业、公司、制造商、监管机构、研究机构 |
| `model` | 型号 | 型号、产品、发动机型号、部件型号、平台 |
| `material` | 材料 | 材料、合金、涂层、复合材料、工艺材料 |
| `parameter` | 参数 | 参数、性能参数、技术指标、数值、规格 |
| `time` | 时间 | 时间、日期、年份、阶段、里程碑 |
| `other` | 其他 | 无法归入以上类别的实体 |

预测实体和金标准实体必须先归入相同稳定类别，才允许互相匹配。这样可以防止同名机构、材料或参数之间误匹配。

### 名称匹配

机构、型号、材料、时间和其他实体按以下顺序生成名称候选：

1. 主名称；
2. 金标准中的 `aliases`；
3. 项目现有的中英文等价词表；
4. 去除大小写、空白、连接符、常见标点后的归一形式。

两个实体只要任一预测候选与任一金标准候选完全相等，即视为名称匹配。为避免短字符串包含造成误报，不继续使用任意子串包含作为严格正确条件。

### 参数匹配

参数实体必须同时满足：

1. 类别均为 `parameter`；
2. 参数名称按上述规则匹配；
3. 双方都提供数值时，换算到相同单位后相对误差不超过该金标准记录的 `tolerance`，默认值为 `0.01`；
4. 只有一方提供数值时不得判为严格匹配；
5. 双方都未提供数值时按名称匹配，但运行记录标记 `name_only_parameter_match`，便于审计。

第一期单位归一覆盖商用航空发动机报告中最常见的同量纲单位：

- 推力：`N`、`kN`、`lbf`；
- 质量：`g`、`kg`、`t`、`lb`；
- 长度：`mm`、`cm`、`m`、`in`；
- 压力：`Pa`、`kPa`、`MPa`、`bar`、`psi`；
- 温度：`°C`、`K`、`°F`；
- 时间：`s`、`min`、`h`；
- 转速：`rpm`；
- 百分比：`%`。

同量纲单位先换算到基准单位。单位未知、量纲不同或无法解析时不自动判为正确，并在运行记录中记录 `unit_mismatch` 或 `unparseable_value`。

### 一对一匹配

使用确定性的一对一匹配，金标准和预测实体均最多参与一次匹配。候选优先级依次为：完全名称与完全值匹配、别名与完全值匹配、名称与容差内值匹配、纯名称匹配。相同优先级时按原始输入顺序选择，保证结果可复现。

## 指标定义

对每个类别及全部类别计算：

- `TP`：成功匹配的预测实体数；
- `FP`：未匹配的预测实体数；
- `FN`：未匹配的金标准实体数；
- `precision = TP / (TP + FP)`；
- `recall = TP / (TP + FN)`；
- `f1 = 2 * precision * recall / (precision + recall)`。

当分母为零时，对应指标返回 `null`，界面显示 `—`，不得用 0 冒充已测得分数。综合指标使用所有类别 TP、FP、FN 汇总后的微平均。实体达标条件固定为综合 F1 不低于 `0.90`。

没有金标准时不返回严格 Precision、Recall 或 F1。系统继续运行现有实体证据自动核验，并将其 `auto_evidence_accuracy` 暴露为 `proxy_evidence_support_rate`，同时返回 `mode = "proxy"` 和解释文本。

## 公开溯源链接可访问率

公开链接测评只处理报告最终正文实际出现的唯一 `http://` 或 `https://` URL。相同 URL 出现多次只计一次。

- HTTP 成功响应和可正常跟随的重定向记为可访问；
- 超时、DNS 错误、TLS/证书错误、连接错误、403、404 和 5xx 记为不可访问；
- `accessibility_rate = accessible_count / checked_count`；
- 达标条件固定为可访问率不低于 `0.98`；
- 没有公开链接时可访问率返回 `null`，状态为 `no_public_urls`，不判为 0 分或未达标。

本功能不使用已有的 URL 正文支撑度结果作为用户要求的“链接准确率”，也不评价来源权威性。现有内部支撑度检查仍可用于报告质量控制，但不出现在本测评面板的核心指标中。

## 后端结构

### 组件职责

1. `gpt_researcher/evaluation/entity_evaluator.py`
   - 负责金标准加载和校验、类别归一、名称与参数匹配、分类与综合指标计算；
   - 保留现有报告实体抽取和无金标准时的证据代理测评。

2. `gpt_researcher/evaluation/evaluation_summary.py`
   - 新建聚合层，将实体结果和 URL 可访问性结果转换为稳定的前端结构；
   - 不读取报告、不访问网络、不重新执行测评，便于独立单元测试。

3. `three_agent_service.py`
   - 继续在最终正文上调用实体测评和 URL 可访问性检查；
   - 构造 `evaluation_summary`，写入 `run_statistics` 并随报告接口返回。

4. `frontend/index.html`、`frontend/scripts.js`、`frontend/styles.css`
   - 在报告质量状态与正文之间增加测评摘要卡和可折叠分类表；
   - 根据严格、代理、无链接和错误状态渲染不同文案。

### 接口结构

`run_statistics.evaluation_summary` 使用以下稳定结构：

```json
{
  "status": "completed",
  "entity": {
    "mode": "strict",
    "status": "completed",
    "ground_truth_path": "outputs/records/entity_ground_truths/example.json",
    "threshold": 0.9,
    "overall": {
      "true_positive": 18,
      "false_positive": 1,
      "false_negative": 2,
      "precision": 0.9474,
      "recall": 0.9,
      "f1": 0.9231,
      "requirement_met": true
    },
    "categories": {
      "organization": {
        "label": "机构",
        "true_positive": 4,
        "false_positive": 0,
        "false_negative": 0,
        "precision": 1.0,
        "recall": 1.0,
        "f1": 1.0
      }
    },
    "proxy_evidence_support_rate": null,
    "message": "已根据任务金标准计算严格实体指标。"
  },
  "public_links": {
    "status": "completed",
    "threshold": 0.98,
    "total_count": 72,
    "checked_count": 72,
    "accessible_count": 71,
    "inaccessible_count": 1,
    "accessibility_rate": 0.9861,
    "requirement_met": true
  },
  "errors": []
}
```

无金标准时 `entity.mode` 为 `proxy`，`overall` 为 `null`，`proxy_evidence_support_rate` 为已有自动证据核验分数。金标准无效时 `entity.status` 为 `invalid_ground_truth`，并在 `errors` 中提供安全、可展示的文件名和原因；不得泄露密钥或文件内容。

## 前端设计

测评面板位于 `reportQualityStatus` 下方、报告正文上方，报告生成期间隐藏，成功取得接口结果后显示。

顶部三张卡片依次为：

1. 实体 F1；
2. 实体召回率；
3. 链接可访问率。

严格实体指标和链接指标达到固定阈值时使用绿色状态，未达标时使用橙红色状态。指标为 `null` 时使用中性状态和明确文本：

- 无金标准：前两张卡显示“待标准答案”，面板另显示“证据支撑率（代理指标）”；
- 无公开链接：第三张卡显示“无公开链接”；
- 金标准无效：实体卡显示“标准答案错误”，并显示文件名和错误原因；
- 测评异常：卡片显示“测评未完成”，报告正文和下载按钮仍正常可用。

“查看分类明细”按钮展开表格，表格列为类别、TP、FP、FN、Precision、Recall、F1。未产生该类别数据的指标显示 `—`。第一期不显示逐条实体明细。

每次启动新报告时清空上一次测评面板，避免旧分数与新任务混淆。页面状态和颜色不能成为唯一信息载体，所有状态都必须同时有文字。

## 错误处理与降级

- 金标准不存在：返回代理模式，不产生错误；
- 金标准 JSON 损坏或结构无效：标记 `invalid_ground_truth`，报告继续导出；
- 实体表未找到：严格模式下预测集合为空，若金标准非空则 Recall 为 0、F1 为 0；代理模式下返回 `no_entity_table_found`；
- 参数值或单位无法解析：该预测项不匹配，保留审计原因；
- 个别 URL 检查失败：计为不可访问并继续检查其他链接；
- URL 检查整体异常：链接状态标记为 `evaluation_failed`，不影响报告导出；
- 聚合层异常：顶层状态标记为 `partial` 或 `failed`，保留仍然有效的另一类指标；
- 前端缺少 `evaluation_summary`：兼容旧接口，测评面板保持隐藏。

## 测试策略

### 实体算法单元测试

- 机构中英文别名可匹配；
- 材料名称在标点和大小写归一后可匹配；
- 相同名称但类别不同不得匹配；
- 参数同单位且在默认 ±1% 范围内可匹配，超出范围不得匹配；
- 单项 `tolerance` 覆盖默认容差；
- 常见同量纲单位换算后可匹配；
- 未知单位、不同量纲和不可解析值不得匹配；
- 一对一匹配不会重复使用同一预测或金标准实体；
- 分类和微平均 Precision、Recall、F1 与手工结果一致；
- 零分母返回 `null`；
- 金标准不存在、合法、损坏和任务不匹配四种状态正确。

### URL 和聚合测试

- 唯一 URL 去重；
- 成功、重定向、超时、403、404、5xx 和连接错误分类正确；
- 98% 边界值达标，低于 98% 不达标；
- 无公开链接返回 `null` 和 `no_public_urls`；
- 实体严格、实体代理、链接失败和部分成功均能生成稳定 `evaluation_summary`。

URL 自动测试使用本地受控 HTTP 服务或替换底层网络读取函数，不依赖公网实时状态。

### 流水线与前端测试

- 报告服务在测评后写入 `run_statistics.evaluation_summary`；
- 测评异常不阻止 Markdown、Word 和 PDF 导出；
- 严格模式渲染三个核心分数与分类表；
- 代理模式不把证据支撑率标成准确率；
- 无公开链接、标准答案错误和测评异常状态文案正确；
- 新任务启动时清空旧测评面板；
- 前端脚本语法检查通过；
- 现有正式报告、模型选择、导出和最终化测试无回归。

## 验收标准

1. 放入合法任务同名金标准后，报告完成页显示综合实体 Precision、Recall、F1 和分类指标；
2. 参数匹配遵守单位换算和默认 ±1% 容差；
3. 综合实体 F1 达到 90% 时显示达标，否则显示未达标；
4. 公开链接可访问率达到 98% 时显示达标，否则显示未达标；
5. 没有金标准时只显示证据支撑率代理指标，不显示伪造的实体准确率；
6. 没有公开链接时显示“无公开链接”，不显示 0%；
7. 金标准损坏、URL 检查失败或聚合失败时报告仍可导出；
8. 完整测评结果可在运行记录中追溯，前端仅展示汇总与分类指标；
9. 所有新增和相关回归测试通过。

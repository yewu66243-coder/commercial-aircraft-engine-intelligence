# 正式报告规范清理与实体、公开溯源测评功能设计

## 背景与目标

现有报告流水线已经能够抽取报告中的核心实体、检查实体是否具备证据，并检查公开 URL 是否可访问或支撑相邻结论。现有自动成稿提示也要求模型不要在确定性断言后追加“证据不足”“本报告不作判断”等兜底表述，但该约束仍依赖模型遵循，没有确定性的成稿规则。因此，正式报告中仍可能出现以下不符合交付规范的语句：

- “受资料范围限制，本报告未取得……原文，不对……作结论”；
- “文献未将该数据与……建立关联，本报告不作此类推断”；
- “文献未说明……，本报告不作该因果推断”；
- “文献未涉及……，本报告不对……作区分性判断”。

本功能同时解决两个问题：

1. 在 Markdown、Word、PDF 共用的最终正文进入导出前，确定性删除上述自我指涉、免责式和否定式兜底语句；
2. 在每次报告生成后自动产生可复现的测评结果，覆盖核心技术实体抽取准确率、公开链接可访问率和公开链接结论支撑准确率，并提供页面摘要以及独立 Word/PDF 测评报告。

实体严格指标只在存在当前任务的标准答案时计算。用户可在网页上传 JSON 或 Excel 标准答案。没有标准答案时，只显示现有证据支撑率代理指标，并明确说明它不能替代准确率。任何测评或测评报告导出失败都不得阻止原研究报告预览和下载。

## 已确认的产品决策

- 标黄的免责、否定式语句从正式报告中直接删除，不移到“待核验事项”。
- 公开信息溯源同时展示“链接可访问率”和“结论支撑准确率”。
- 测评结果同时提供页面面板和独立 Word/PDF 测评报告。
- 标准答案支持网页上传 JSON 或 Excel。
- 每次研究报告生成完成后自动测评，并提供“重新测评”按钮。
- 实体综合 F1 达标线为 90%，链接可访问率达标线为 98%，结论支撑准确率达标线为 90%。

## 范围

### 包含

- 确定性检测和删除正式正文中的自我指涉、免责式及否定式兜底句；
- 删除后清理孤立引用、残句和空段，并保证所有导出格式使用同一份最终正文；
- 保存被删除内容、章节和规则命中原因到后台审计记录；
- 网页上传并校验任务标准答案，支持 JSON 和 `.xlsx`；
- 机构、型号、材料、参数、时间及其他实体的分类和总体 Precision、Recall、F1；
- 参数数值、单位换算和容差匹配；
- 公开链接可访问率；
- 按“报告断言—引用链接”关系计算公开链接结论支撑准确率；
- 报告顶部测评面板、分类明细、标准答案上传、重新测评与下载按钮；
- 独立 Markdown 中间稿、Word 和 PDF 测评报告；
- 测评历史记录和失败降级；
- 算法、接口、导出、前端和完整流水线自动测试。

### 不包含

- 独立于当前系统的批量测评中心；
- 使用大模型自动生成金标准并将其冒充严格准确率；
- 对链接来源机构做主观权威性排名；
- 自动编辑用户上传的标准答案；
- 因测评未达标而阻止研究报告下载；
- 将删除的免责句转移到正式报告其他章节。

## 用户流程

1. 用户在任务配置区选择或上传当前任务的 JSON/Excel 标准答案。标准答案不是启动研究任务的必填项。
2. 用户按现有流程生成报告。
3. 自动成稿校订完成后，系统对导出前最终正文执行规范语句清理，并在删除后重新整理段落与引用。
4. 系统使用清理后的最终正文执行实体测评、URL 可访问性检查和断言支撑检查。
5. 系统继续导出原研究报告的 Markdown、Word 和 PDF。
6. 前端在正式报告正文上方显示四项核心指标、分类表和操作按钮。
7. 系统生成独立测评报告，用户可下载 Word 或 PDF。
8. 用户替换标准答案后可点击“重新测评”；系统复用已保存的最终正文和来源记录，不重新检索或重写研究报告。
9. 每次自动测评和重新测评都保存独立记录，不覆盖历史结果。

## 正式报告规范语句清理

### 清理位置

清理发生在自动成稿校订之后、实体和链接测评之前、正式报告格式化与导出之前。Markdown、Word 和 PDF 必须从清理后的同一正文生成，避免不同格式出现不同内容。

### 规则类别

清理器仅删除自我指涉和免责式表述，不泛化删除所有包含“未”“不足”“限制”的句子。规则分为以下类别：

1. 报告自我指涉：含“本报告不作”“本报告不进行”“本报告不据此”“本报告无法据此”等表达；
2. 文献缺失加否定动作：同一句或相邻分句同时出现“文献/资料/原文未说明、未涉及、未取得、未建立关联”和“不作判断、推断、结论、区分”等表达；
3. 资料边界兜底：以“受资料范围限制”“鉴于证据不足”等开头，后续仅表达不判断、不推断或不作结论；
4. 否定前文结论：先陈述确定性断言，随后仅用“因此无法证实”“故不作确定性结论”等内容撤回该断言。

正常且有信息量的范围说明保留，例如“样本覆盖 2024—2026 年公开资料”“本次共纳入 15 份可读取原文”。清理器不得删除客观描述样本、时间、来源数量或方法边界的句子。

### 删除粒度

- 默认按完整句删除，包括与该句绑定的行内引用；
- 同一段删除后只剩孤立引用、标点、连接词或无主残句时，删除整个段落；
- 表格单元格命中时删除该单元格中的违规句，单元格无实质内容时将其置为“—”；整行失去实质信息时删除该行；
- 摘要、正文、结论和图表说明使用同一规则；
- 删除后执行现有引用归一和空段清理，禁止保留悬空引用；
- 被删除文本不进入正式报告的“待核验事项”或“研究局限”。

### 审计结构

运行记录新增 `report_style_cleanup`：

```json
{
  "version": "formal-style-cleanup-v1",
  "removed_count": 3,
  "removed_items": [
    {
      "section": "3.2 适航要求",
      "rule": "self_referential_disclaimer",
      "text": "本报告不作确定性结论。"
    }
  ]
}
```

审计内容只保存到后台运行记录，不显示在正式报告或测评报告正文中。记录不得包含密钥、请求头或未公开文件内容。

## 标准答案上传与校验

### 存储与任务绑定

标准答案存放在：

```text
outputs/records/entity_ground_truths/
```

服务端使用当前任务名称的安全摘要生成文件名，不信任浏览器提供的路径。上传文件只允许 `.json` 和 `.xlsx`，限制文件大小，并使用临时文件解析成功后原子替换正式文件。用户上传的新版本替换当前任务的活动标准答案，但历史测评记录保留当时文件的安全文件名、内容摘要和测评时间。

### JSON 结构

```json
{
  "task": "任务名称",
  "entities": [
    {
      "type": "机构",
      "name": "Pratt & Whitney",
      "aliases": ["普惠", "P&W"]
    },
    {
      "type": "材料",
      "name": "粉末金属"
    },
    {
      "type": "参数",
      "name": "起飞推力",
      "value": 33110,
      "unit": "lbf",
      "tolerance": 0.01
    }
  ]
}
```

### Excel 结构

Excel 读取第一个可见工作表，表头必须位于第一行：

| 列名 | 必填 | 含义 |
| --- | --- | --- |
| `类别` | 是 | 机构、型号、材料、参数、时间或其他 |
| `名称` | 是 | 标准实体名称 |
| `别名` | 否 | 多个别名使用中英文分号分隔 |
| `数值` | 参数按需 | 参数标准值 |
| `单位` | 参数按需 | `kN`、`MPa`、`℃`、`rpm` 等 |
| `容差` | 否 | 非负相对误差，默认 `0.01` |

空白数据行忽略。服务端错误消息必须指出工作表、Excel 行号和字段，例如“标准答案.xlsx / Sheet1 / 第 8 行：类别不能为空”。公式单元格只读取工作簿保存的结果，不执行宏或外部链接。

### 校验规则

- `task` 缺失时由当前任务注入；存在时必须与当前任务完全一致；
- `entities` 必须是非空数组；
- `type` 和 `name` 必须是非空字符串；
- `aliases` 必须为字符串列表或 Excel 分号分隔文本；
- `value` 必须为数字或可解析数字字符串；
- `tolerance` 必须为非负有限小数；
- 重复的同类别、同名称、同数值实体在校验阶段报错，不静默去重；
- 文件不存在与文件无效是两个不同状态：不存在进入代理模式，无效显示 `invalid_ground_truth`。

## 实体归一与匹配

### 类别归一

| 稳定标识 | 中文显示名 | 可接受别名示例 |
| --- | --- | --- |
| `organization` | 机构 | 机构、企业、公司、制造商、监管机构、研究机构 |
| `model` | 型号 | 型号、产品、发动机型号、部件型号、平台 |
| `material` | 材料 | 材料、合金、涂层、复合材料、工艺材料 |
| `parameter` | 参数 | 参数、性能参数、技术指标、数值、规格 |
| `time` | 时间 | 时间、日期、年份、阶段、里程碑 |
| `other` | 其他 | 无法归入以上类别的实体 |

预测实体和标准实体必须属于相同稳定类别才允许匹配，防止同名机构、材料或参数相互误配。

### 名称与别名匹配

候选名称依次包括主名称、标准答案别名、项目已有中英文等价词及去除大小写、空白、连接符和常见标点后的归一形式。任一预测候选与任一标准候选完全相等时名称匹配。严格指标不得使用任意子串包含，避免短名称误报。

### 参数匹配

参数实体必须同时满足：

1. 类别均为 `parameter`；
2. 参数名称匹配；
3. 双方均有数值时，换算为同一基准单位后的相对误差不超过标准答案记录的 `tolerance`，默认 1%；
4. 只有一方提供数值时不判为严格匹配；
5. 双方均未提供数值时允许名称匹配，但审计记录标记 `name_only_parameter_match`。

第一期单位换算覆盖：

- 推力：`N`、`kN`、`lbf`；
- 质量：`g`、`kg`、`t`、`lb`；
- 长度：`mm`、`cm`、`m`、`in`；
- 压力：`Pa`、`kPa`、`MPa`、`bar`、`psi`；
- 温度：`°C`、`K`、`°F`；
- 时间：`s`、`min`、`h`；
- 转速：`rpm`；
- 比例：`%`。

单位未知、量纲不同或数值不可解析时不匹配，并记录 `unit_mismatch` 或 `unparseable_value`。

### 一对一匹配与指标

预测实体和标准实体均最多参与一次匹配。候选优先级为：完全名称与完全值、别名与完全值、名称与容差内值、纯名称。相同优先级按输入顺序选择，保证结果可复现。

对每个类别和全部类别计算：

- `TP`：成功匹配的预测实体数；
- `FP`：未匹配的预测实体数；
- `FN`：未匹配的标准实体数；
- `precision = TP / (TP + FP)`；
- `recall = TP / (TP + FN)`；
- `f1 = 2 * precision * recall / (precision + recall)`。

分母为零时返回 `null`，界面显示“—”，不得用 0 冒充已测分数。总体指标采用微平均。实体综合 F1 不低于 0.90 时达标。

无标准答案时不返回严格 Precision、Recall 或 F1。系统暴露已有 `auto_evidence_accuracy` 为 `proxy_evidence_support_rate`，同时返回 `mode = "proxy"` 和“该指标不能替代实体准确率”的说明。

## 公开信息溯源双重测评

### 链接可访问率

可访问率按清理后最终正文实际引用的唯一 HTTP/HTTPS URL 统计：

- 成功响应和可正常跟随的重定向记为可访问；
- 超时、DNS、TLS/证书、连接错误、403、404 和 5xx 记为不可访问；
- `accessibility_rate = accessible_unique_urls / unique_public_urls`；
- 达标线为 0.98；
- 无公开链接时返回 `null` 和 `no_public_urls`，不判为 0 分。

同一 URL 在不同位置出现多次，在可访问率中只计一次。

### 结论支撑准确率

结论支撑准确率按“报告断言—引用链接”关系统计。同一 URL 支撑三个不同断言时产生三条关系：

- `supported`：链接正文完整支持相邻报告断言；
- `partially_supported`：只支持断言的一部分；
- `unsupported`：链接内容与断言不符；
- `unchecked`：正文无法读取或无法提取。

只有 `supported` 计入正确项：

```text
support_accuracy = supported_relationships / all_public_url_relationships
```

部分支持、未支持和未核验均计入分母但不计入分子。达标线为 0.90。测评复用项目现有公开 URL 支撑评估器及其固定文本匹配规则，不使用随机大模型判分。逐条结果必须保存报告断言、公开 URL、状态和安全失败原因，便于复核。

### 清理与测评顺序

规范语句清理先于链接测评。删除违规句时一并删除其引用关系，避免已从正式报告移除的句子继续进入测评分母。公开链接测评不得修改研究报告正文；其结果只进入测评记录和测评报告。

## 后端组件与接口

### 组件职责

1. `backend/reporting/finalization.py`
   - 识别并删除不符合规范的免责、否定式句子；
   - 清理残句、空段和悬空引用；
   - 产生 `report_style_cleanup` 审计信息。

2. `gpt_researcher/evaluation/entity_evaluator.py`
   - 加载和校验任务标准答案；
   - 负责类别、名称、参数、单位和一对一匹配；
   - 输出总体、分类和逐条实体结果。

3. `gpt_researcher/evaluation/ground_truth_io.py`
   - 负责 JSON/Excel 解析、统一数据结构、行号错误和安全持久化；
   - 不执行实体匹配，保持上传校验与评分算法分离。

4. `gpt_researcher/evaluation/source_evaluator.py`
   - 保留公开链接可访问性检查；
   - 输出每条“断言—链接”关系的支撑状态及汇总准确率。

5. `gpt_researcher/evaluation/evaluation_summary.py`
   - 将实体、可访问性和支撑结果转换为稳定前端结构；
   - 不读取报告、不访问网络、不重新评分，便于单元测试。

6. `backend/reporting/evaluation_report.py`
   - 将稳定测评结果渲染为独立 Markdown；
   - 复用现有文档导出器生成 Word 和 PDF。

7. `three_agent_service.py`
   - 在最终正文上依次执行规范清理和三类测评；
   - 将测评摘要、明细、审计信息和下载路径写入运行记录；
   - 支持对已完成报告重新测评。

8. `main.py`
   - 提供标准答案上传、重新测评和测评报告下载接口；
   - 使用现有 FastAPI 错误结构返回安全、可展示的错误。

9. `frontend/index.html`、`frontend/evaluation_panel.js`、`frontend/scripts.js`、`frontend/styles.css`
   - 渲染四项指标、分类表、上传与操作按钮；
   - 新任务启动时清空旧状态；
   - 保证颜色不是唯一状态信息。

### 接口行为

- `POST /api/evaluation-ground-truth`：接收 `task` 与 JSON/Excel 文件，校验成功后保存并返回实体数量、类别计数和文件摘要；
- `POST /api/report-evaluation/{run_id}`：复用指定运行记录（`run_statistics.run_id`）已保存的最终正文和来源记录重新测评，返回新的 `evaluation_summary` 和下载路径；记录不存在返回 404，缺少正文或任务信息返回 409；
- 测评报告由现有 `/outputs/...` 静态文件机制下载，不新增不受控文件读取接口；
- 原 `/api/three-agent-report` 响应继续在 `run_statistics.evaluation_summary` 返回测评结果，并增加 `evaluation_report_paths`。

## 页面设计

测评面板位于报告质量状态下方、正式报告正文上方。生成期间隐藏，获得结果后显示。

顶部四张卡片依次为：

1. 实体 Precision；
2. 实体 Recall / F1；
3. 链接可访问率；
4. 结论支撑准确率。

实体卡在严格模式显示数字和 90% 达标状态；代理模式显示“待标准答案”，并在面板说明中单独显示“证据支撑率（代理指标）”。链接无数据时显示“无公开链接”。指标为 `null` 时显示“—”或具体状态，不显示 0%。

面板操作区包括：

- “上传/替换标准答案”；
- 当前标准答案文件名和校验状态；
- “重新测评”；
- “下载测评报告 Word”；
- “下载测评报告 PDF”；
- “查看分类明细”。

分类表列为类别、TP、FP、FN、Precision、Recall、F1。独立测评报告额外显示匹配实体、误抽实体、漏抽实体和链接逐项明细；页面默认不展开这些长列表。

绿色表示达标、橙红色表示未达标、中性色表示无数据或代理模式。每种颜色都同时显示“达标”“未达标”“待标准答案”“无公开链接”或“测评未完成”等文字。

## 独立测评报告

独立测评报告包含：

1. 任务名称、测评时间、报告标识和标准答案文件摘要；
2. 指标定义和达标线；
3. 总体实体 Precision、Recall、F1；
4. 各实体类别 TP、FP、FN、Precision、Recall、F1；
5. 匹配实体、误抽实体和漏抽实体；
6. 链接可访问率和逐 URL 状态；
7. 结论支撑准确率和逐条“断言—链接”结果；
8. 无数据、解析错误、网络错误和降级说明；
9. 原正式报告规范清理数量，不复述被删除的免责句原文。

测评报告只记录评分事实，不复制研究报告正文，也不重新调用生成模型。Word 与 PDF 从同一 Markdown 中间稿生成，文件保存在 `outputs/evaluations/`，名称包含任务安全名称、报告标识和测评时间，避免覆盖历史结果。

## 错误处理与降级

- 标准答案不存在：进入代理模式，不产生系统错误；
- JSON/Excel 损坏或结构无效：返回 `invalid_ground_truth`，显示文件名、工作表、行号和安全原因；
- 实体表未找到：严格模式下预测集合为空，标准答案非空时 Recall 和 F1 为 0；代理模式返回 `no_entity_table_found`；
- 参数值或单位无法解析：该项不匹配并保留审计原因；
- 个别 URL 访问失败：记录为不可访问并继续其他链接；
- URL 正文无法读取：可访问性仍按实际响应统计，支撑关系记为 `unchecked`；
- 任一测评子模块整体异常：该部分状态为 `evaluation_failed`，保留其他成功指标；
- 测评报告 Word 或 PDF 导出失败：另一格式和页面指标继续可用；
- 重新测评缺少已保存正文或来源记录：返回明确错误，不重新运行研究任务；
- 前端收到旧响应且缺少 `evaluation_summary`：测评面板保持隐藏；
- 任何测评异常均不改变原研究报告的下载状态。

## 测试策略

### 规范语句清理

- 六张用户示例中的句式均被删除；
- “样本覆盖 2024—2026 年公开资料”等正常范围说明保留；
- 一个段落包含正常句与违规句时只删除违规句；
- 删除后孤立引用、残句、空段和空表格行被清理；
- 摘要、正文、结论和表格使用同一规则；
- Markdown、Word、PDF 的正文来源一致；
- 后台审计包含规则和章节，正式报告不包含被删除原文。

### 标准答案输入

- 合法 JSON 与 Excel 解析为同一内部结构；
- Excel 别名分号拆分正确；
- 文件扩展名、大小、空文件、缺列、空字段、非法数值、负容差和重复实体均返回明确错误；
- Excel 错误包含工作表和实际行号；
- 任务不匹配被拒绝；
- 临时文件在成功或失败后均正确清理；
- 浏览器文件名不能造成目录穿越或覆盖无关文件。

### 实体算法

- 机构中英文别名可匹配；
- 材料名称经标点和大小写归一后可匹配；
- 同名不同类别不得匹配；
- 参数同单位且在默认 ±1% 内匹配，超出范围不匹配；
- 单项容差覆盖默认值；
- 常见同量纲单位换算后匹配；
- 未知单位、不同量纲和不可解析值不匹配；
- 一对一匹配不会重复使用实体；
- 分类和微平均指标与手工结果一致；
- 零分母返回 `null`；
- 无标准答案、合法、损坏和任务不匹配四种状态正确。

### URL 与聚合

- 可访问率按唯一 URL 去重；
- 支撑准确率按“断言—链接”关系计数，不按 URL 去重；
- 成功、重定向、超时、403、404、5xx 和连接错误分类正确；
- 完整支持计入分子，部分支持、未支持和未核验只计入分母；
- 98% 和 90% 边界值判断正确；
- 无公开链接返回 `null` 和 `no_public_urls`；
- 实体严格、实体代理、单项失败和部分成功均产生稳定摘要；
- 网络测试使用本地受控 HTTP 服务或替换底层读取函数，不依赖公网实时状态。

### 流水线、导出与前端

- 自动生成结束后写入 `evaluation_summary` 和独立报告路径；
- 重新测评不调用研究、写作或成稿模型；
- 测评异常不阻止原报告 Markdown、Word、PDF 导出；
- 测评报告 Word/PDF 包含相同指标和逐项明细；
- 严格模式渲染四项指标和分类表；
- 代理模式不把证据支撑率标成准确率；
- 无公开链接、标准答案错误和测评异常文案正确；
- 新任务启动时清空旧面板；
- 替换标准答案后重新测评产生新历史记录；
- 前端脚本语法检查通过；
- 现有报告生成、正式排版、模型选择、上传和安全测试无回归。

## 验收标准

1. 六类用户截图中的免责、否定式句子不再出现在新生成的 Markdown、Word 或 PDF 正式报告中；
2. 正常、有实际信息量的研究范围说明仍然保留；
3. 用户可在网页上传合法 JSON 或 Excel 标准答案，错误文件显示具体行级原因；
4. 有合法标准答案时显示总体和分类实体 Precision、Recall、F1；
5. 参数匹配遵守单位换算和默认 ±1% 容差；
6. 实体综合 F1 达到 90% 时显示达标，否则显示未达标；
7. 页面同时显示链接可访问率和结论支撑准确率；
8. 链接可访问率达到 98%、结论支撑准确率达到 90% 时分别显示达标；
9. 没有标准答案时只显示证据支撑率代理指标，不显示伪造的实体准确率；
10. 没有公开链接时显示“无公开链接”，不显示 0%；
11. 用户可在不重新生成研究报告的情况下替换标准答案并重新测评；
12. 用户可下载独立 Word/PDF 测评报告，内容包含总体、分类和逐项明细；
13. 标准答案损坏、URL 检查失败、评分失败或测评报告导出失败时，原研究报告仍可预览和下载；
14. 每次测评结果、标准答案摘要、规范清理数量和下载路径可在运行记录中追溯；
15. 所有新增测试和相关回归测试通过。

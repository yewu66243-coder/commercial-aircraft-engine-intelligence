## 2. 当前系统已具备的核心能力

系统当前是一个面向商用航空发动机情报收集的本地 Web 工作台，主要能力包括：

- 前端任务配置、模板选择、检索范围选择、长短报告选择、大模型选择。

## 4. 报告生成链路概览

### 4.1 三智能体主流程

入口在 `three_agent_service.py`。

主要阶段：

1. 任务初始化，解析报告类型、报告长短、模型运行时。
2. 预检索摘要、本地资料库、源站模板等。
3. 规划 Agent：根据任务和领域主题规划子题。
4. Research Agent：每个子题检索并生成研究材料。
5. Librarian Agent：从摘要索引和全文 RAG 中补充本地资料。
6. Writer Agent：汇总研究材料，生成完整 Markdown 草稿。
7. Content depth review：检查正文篇幅、专题覆盖、重复、AI 味、兜底表述、资料罗列。
8. Enrichment/argument polish：必要时补充和重组报告。
9. Editorial Agent：对照原文进行成稿校订和来源复查。
10. Citation/formatting：整理引用、参考文献和正式报告结构。
11. 导出 Markdown、Word、PDF。
12. 保存 evaluation record。

### 4.2 报告框架

`backend/reporting/framework.py` 会按任务语义选择框架：

- `airworthiness_maintenance_monitoring`：适航与维修措施监测
- `patent_landscape`：专利布局分析
- `technical_route_research`：技术路线研究
- `market_supply_chain`：市场与供应链影响
- `model_tracking`：型号动态跟踪

公开正文默认不固定写“资料来源与研究方法”。资料来源、检索范围、源站权重等一般进入后台记录、内部核验，或在引言/综合讨论中简述。

## 5. 参考文献处理上下文

用户要求参考文献接近 GB/T 7714-2025，而不是简单：

```text
[1]赵平.发动机制造商加大MRO网络建设[J].
```

已做处理：

- `backend/reporting/citations.py`：引用注册、编号、文献类型标识和格式化。
- `backend/reporting/reference_metadata.py`：从本地 PDF 页面中提取刊名、年份、期号、页码、DOI、专利号、公告日、申请人等。
- `backend/reporting/reference_lookup.py`：按题名分层联网检索和缓存元数据。注意当前命令行环境可能受网络/证书/沙箱限制，实际应用环境不一定同样受限。
- `backend/reporting/formal_report.py`：把参考文献著录缺项写入 `report_quality.reference_metadata_issues`。
- 前端会显示“参考文献待补全”之类的质量提示。

重要原则：

- 不得编造作者、刊名、年份、期号、页码、DOI、专利号。
- DOI 不自动意味着 `[J/OL]`。结构化刊物信息完整的本地期刊文章仍优先 `[J]`。
- 明确 `online_first` 才可用 `[J/OL]` 并放访问日期/URL。
- 无法补齐的参考文献保留为待补全，不应伪装成完整 GB/T 格式。

### 6.3 用户上传资料后的实际流程

前端上传入口：

- `frontend/scripts.js`
- API：`POST /api/local-library/upload`

后端流程：

1. `main.py` 的 `/api/local-library/upload` 接收文件。
2. 调用 `save_local_library_file()` 保存到目标库。
3. 立即写入对应摘要索引。
4. 调用 `enqueue_upload_index_job()` 加入全文索引队列。
5. 调用 `ensure_upload_index_worker()` 启动后台 worker。
6. worker 调用 `build_library_index(repair=True, source_paths=[path])`，只处理这个新文件。
7. 成功后写入 `library.sqlite3` 的 `documents` 和 `chunks`。
8. 前端轮询 `/api/local-library/index-jobs`，显示状态：
   - `queued`
   - `waiting`
   - `indexing`
   - `ready`
   - `partial`
   - `failed`

相关文件：

- `main.py`
- `gpt_researcher/document/upload_indexing.py`
- `upload_index_worker.py`
- `gpt_researcher/document/library_rag.py`
- `frontend/scripts.js`

如果全文索引失败，摘要索引仍然存在，但全文 RAG 不会使用该文件。

## 12. 重要设计原则

### 12.1 报告质量原则

- 不要为了篇幅编造事实。
- 不要把未报道解释为不存在。
- 不要把 OEM 改进计划等同于监管适航指令。
- 不要把计划产能当作实际产出。
- 不要把历史预测当作当前事实。
- 不要把相关关系写成因果关系。
- 缺证据的断言不要写进公开正文后再加免责声明。
- 资料缺口集中在综合讨论、后续监测重点或内部核验记录。

### 12.2 引用原则

- 正文使用内部来源编号 `[原文1]`、`[URL1]`，系统统一转换为公开编号。
- 本地来源必须对应真实精读文件。
- 参考文献缺字段时宁可提示待补全，也不能伪造。
- 参考文献著录缺项应进入 `report_quality.reference_metadata_issues`。

### 12.3 RAG 原则

- 摘要索引用于快速筛选资料。
- 全文向量索引用于召回正文片段。
- 二者是互补关系，不是二选一。
- 上传新文件后应同时有摘要索引和全文索引任务。
- 全文索引失败不应阻塞摘要索引，但应在前端显示失败原因。

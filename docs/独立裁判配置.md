# 独立裁判配置

报告完成写作与审校后，系统将实体/参数候选、公开URL引用句及本轮已保存原文提交给单独配置的模型核验。使用OpenAI兼容的Chat Completions接口；裁判不会继承写作模型的API Key。无需新增前端操作。

## 配置

在项目根目录 `.env` 开头填写以下三项，保存后重启后端：

```dotenv
JUDGE_ENABLED=true
JUDGE_API_KEY=填写裁判服务的密钥
JUDGE_BASE_URL=填写服务提供方的兼容接口根地址
JUDGE_MODEL=填写实际可用模型名
```

BASE_URL使用服务商提供的API根地址，通常以 `/v1` 结尾，不填写网页聊天地址或完整 `/chat/completions` 路径。选择与当次写作模型不同的模型；如果名称相同，系统跳过裁判并提示更换。调用时会向这个服务发送待核验表述及相关本地论文/网页原文片段。

其余参数已预置：单次请求60秒、裁判请求阶段总预算180秒、每批6项、最多提交300项、并发2。可在 `.env` 的 `JUDGE_REQUEST_TIMEOUT_SECONDS`、`JUDGE_TOTAL_TIMEOUT_SECONDS`、`JUDGE_BATCH_SIZE`、`JUDGE_MAX_ITEMS`、`JUDGE_CONCURRENCY` 调整。样本上限与预算用于约束延迟及调用量，未完成项不会从统计中删除。

## 结果与口径

裁判逐项输出正确、错误、证据不足，并给出理由和原文摘录。程序验证正确/错误判定所附摘录确实存在于提交的原文中；不存在、遗漏ID、重复ID、输出截断等情况保留为未核验。摘录验证只能校验出处，不能完全保证模型语义判断正确。

实体指标：正确候选数 / 全部抽取候选数，不评估漏抽；同一实体在不同句中的表述分别核验。公开链接指标：以正文实际引用的URL编号为单位，一个编号关联的全部判断均被支持才算正确。无URL引用时该项未测，不能用本地来源替代。

证据不足、无引用、超限或调用失败的样本仍留在分母中；存在待核验项时不宣布达标。缺少配置时保留规则初筛。接口出错不阻止研究报告导出，错误类别及待核验原因会写入测评报告。

裁判模型、耗时、样本覆盖、逐项理由、原文片段及页码存入测评JSON和运行记录，Word展示汇总与部分问题明细。裁判耗时纳入后端总耗时，不额外凑够某个时长。

该模块只核对报告是否忠实于给定证据，不能证明来源本身绝对真实。候选提取仍是现有实体表/正文规则，独立裁判并不等于完整实体召回评估。至少10轮验收仍需实际执行并保存结果。

## 联调

填好配置后先运行一次正常研究任务，检查运行日志出现独立裁判的分批处理消息，下载“指标测评”查看独立裁判章节。若显示未配置、模型同名、无样本或调用失败，按相应提示处理。密钥留空时不向任何裁判服务发请求。

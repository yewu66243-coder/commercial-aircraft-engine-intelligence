# 人工指标核验操作说明

本流程代替独立大模型裁判，不改变报告写作和成稿审校。客户前端不新增测评按钮。
现有自动规则测评仅是初筛记录，不能用其分数代替人工验收结论；历史模型裁判记录保留但不参与新核验计分。

## 1. 获取核验表

重启系统加载新代码。新报告导出后，在项目`outputs/manual_reviews`下自动生成核验包，包含Excel、最终Markdown副本、证据HTML及JSON快照。
核验表只提取最终保存正文中的实体、参数和实际引用的网址，包含摘要及正文表格，不从任务名、候选资料、检索结果或参考文献列表单独增加对象。
正文直接出现的HTTP(S)链接，以及正文引用编号明确对应的公开网址，均进入“溯源核验”。仅在文末列出但未被正文引用的网址不纳入；本地论文文末的DOI元数据不冒充网页事实引用。同一网址用于不同原句时逐条核对，“任务与规则”另列去重网址数。
实体行保留正文原句、章节及段落或表格位置。没有明确引用、不具备来源文件或URL的行在导出前从主表移除，不另存删除明细，也不移入提取审计，不自动检索候选材料冒充正文引用。引用材料仅用于辅助核对，不是新增核验对象。
核验材料准备失败不会丢弃研究报告，可在项目目录打开PowerShell重新导出。维护工具使用项目自带的便携Python，无需安装新的模型或配置API。
旧核验包不覆盖，仍可按原规则导入。正式采用新的“仅正文”口径时，应重新导出并核验；多轮汇总不将旧口径结果冒充新口径结果。

导出前删除“来源文件或URL”为空（包括纯空格、换行或不可见空白）的整行，再清理名称或原句为空、仅有无效符号、明显乱码的无效行，并移除空白或明显乱码的辅助摘录。来源非空、仅摘录缺失或乱码的事实行仍保留。中文、英文、型号、公式和少量特殊字符不因语言或字体而被删除。乱码识别采用保守规则，不能保证发现所有编码异常。仅记录清理数量，不另存删除明细、不转入提取审计，也不增加清理记录文件。移除缺来源事实后，本表只统计保留样本，不据此认定全报告达标。此过程不修改报告正文或原资料，不代表报告质量提升或核验通过。已有核验包不自动覆盖，新生成或重新导出的核验包才采用该清理步骤。

```powershell
.\manual_review.bat list
.\manual_review.bat export "实际运行编号"
```

运行编号是`eval-...`，不是报告文件名末尾四位随机码。`list`列出编号和任务，`export`输出核验表及材料路径。历史报告只有最终Markdown原件存在时才能导出，不能拿排版前正文冒充最终报告。

## 2. 填写Excel

“任务与规则”填写核验人、日期（YYYY-MM-DD）；需要排除候选时，由另一人复核并填写复核人。
“实体核验”和“溯源核验”的A至I列是系统原始记录，不要修改或删行。J至M列依次填写人工判定、理由、核验摘录、核验来源及位置。正确项必须附原文摘录和来源位置。

新导出的工作表不启用表格保护，所有单元格均可选择和复制，便于复制来源网址、文件名和摘录进行查证。蓝色区域仍用于填写核验意见；编号、原句、来源、结构化字段与提取审计由后台导入校验，取消表格保护不意味着可以修改这些原始记录。旧表如提示保护，可在Excel或WPS的“审阅”中撤销工作表保护（系统未设置密码），或重新导出核验表。

### 结构化提取规则（v3）

N列起增加只读的属性、数值、完整单位、原始数值表达、时间/条件、语句性质、对象关联方式、引用对应方式及待确认事项。例如“GTF-2型燃油油量表测试仪，检定周期12个月”作为一项对象属性事实，不再拆成设备名称和“12个”两个项目。`GTF Advantage`与`GTF`、`E-Jet E2`与`E-Jet`不会在同一名称位置重复提取；单独出现的系列名称仍保留。

对象或属性无法可靠关联时，保留“对象待确认”“属性待确认”，不从分母删除。此时需核对完整原句，在判定理由中记录实际对象、属性及依据；不得仅因规则未能绑定就认定报告错误。同一对象不同属性、数值、单位、时间或限定语分开判断。程序只合并结构字段及可见分句相同的重复事实，保留全部出现位置、引用和摘录；跨句改写后的语义重复仍需人工检查，不能假设自动去重已完成。

分句有明确引用时按分句核验；句末多个引用只有在唯一文件编号能与已保存且已引用原文对应时才提供对齐建议，并标记待复核。不能确定时保留完整引用组，不把每条链接强行配给每个子事实。引用组对应行须整体核对该URL是否支撑其被用于说明的事实；需要细分时在“漏项与争议”新增子事实，并由另一人复核原复合项的替换排除。

新增“提取审计”表，保留明确建议、研究问题、研究范围说明和未识别到对象/参数的原句。明确的非事实性语句默认不计入事实分母，但分类不是事实判断：请逐条检查，误分或漏抽的事实须在“漏项与争议”补齐。混有已发生事实或数值的建议句保留核验项，不会整段删去。完成审计后，在“任务与规则”的“提取复核确认”填写“确认”；有审计记录而未确认时，导入只保存进度，不判达标。

旧版v1/v2核验包继续按原版本导入，不会自动转换或覆盖；正式使用v3时需重新导出。新旧提取口径的分母不同，不宜直接比较准确率，也不能把规则修正造成的行数变化视为报告质量提升。系统不自动填写“正确”或“错误”，未恢复大模型裁判。

判定使用“正确”“错误”“待核验”“排除”。待核验不算错误，但未完成时不会给出最终准确率或达标结论。排除只用于重复项或明显不属于事先约定范围的候选，不用于隐藏错误或证据不足。排除理由应标明重复编号或具体范围依据；复核人不同于核验人，并在“排除项复核确认”填写“确认”后才可完成计分。

点击“材料入口”打开同目录的`evidence.html`，可以看候选片段、完整已存原文及最终报告。核验包内的HTML/JSON是生成时快照，不等于文件或网页的全部内容；原文未保存完整时须自行打开原始资料补查。网页访问状态与引用正确性分开判断。不要只依据自动选择的一小段材料判定错误。

核验表中的对象必须实际出现于正文，但自动实体识别仍可能漏项，不能据此宣称已完成全量人工检查。须逐段检查最终报告，在“漏项与争议”补充遗漏对象：A列填写`A1`、`A2`等唯一编号；B列填写`entity:参数`、`entity:机构`或`source:公开引用`等；C列填对象；D列保留最终报告原句；F列填来源，公开引用必须为对应URL。J至M列同上。可在此工作表增加行，每张表上限19999个数据行，超过时明确报错而非静默截断。

完成逐段检查及补充后，在“全量检查确认”填写“确认”。自动遗漏不等于可以不核验。Excel的公式只是填写期间的参考，导入后以程序重算结果为准。

## 3. 导入并生成测评报告

保持核验包的HTML/JSON和报告原件不变，可另存填写后的Excel。

```powershell
.\manual_review.bat import "实际运行编号" "D:\实际目录\已填写核验表.xlsx"
```

程序检查运行编号、报告及Word/PDF文件哈希、材料快照、原始行是否被删改、重复项和判定是否合法。存在公式、宏、外部工作簿链接、缺少理由或版本不符时拒绝导入，不产生达标结果。
未填完也可导入保存进度，结果保持待完成。每次成功导入另存一份填写表、结果JSON、Markdown及Word测评报告，不覆盖历史核验。Word转换失败时保留其他结果并明确提示。
正文或导出文件修改后，旧核验表失效；应通过新的报告生成运行重新建立版本。当前工具不把外部修改的Word自动转换为新的已登记报告正文。

## 4. 指标口径

- 生成耗时：后端任务开始至正式报告文件导出完成；人工核验材料准备和填写时间不计入。仍应在验收现场记录用户提交到报告可用的端到端时间，不能把后台计时直接当作浏览器网络耗时。
- 实体准确率：正确实体及属性项数/纳入核验项总数，要求≥90%。同一实体的不同参数、时间或适用条件分别判断，重复事实不重复增加正确数。名称、数值、单位、所属对象及适用条件均须核对。
- 公开溯源准确率：正确的“事实陈述—公开URL”关系数/纳入核验的关系总数，要求≥98%。一条链接被用于不同事实时逐条核对；HTTP 200不能证明引用正确。
- 未全部核验、未确认全量检查或无适用样本时，不作达标判定。零样本不显示100%。不采用部分支撑0.5分；必要时人工拆成独立事实项，并对原复合项注明替换原因后排除。
- 本流程不计算漏抽召回率和F1。若验收另有要求，应事先固定测试资料和人工标准答案。正式测试前须与验收方确认计分单位、去重和范围口径。

## 5. 汇总至少10轮

```powershell
.\manual_review.bat summary "运行编号1" "运行编号2" "运行编号3"
```

实际使用时传入至少10个不同运行编号。汇总采用每轮最近一次人工核验，并再次检查报告是否变化。任一轮待完成或未达标、轮数不足10，不判该组达标；不以平均分代替逐轮要求。汇总JSON、Markdown和Word另存到`outputs/manual_reviews/summaries`。

测评文件含报告原文和证据，按研究资料管理，不对外公开密钥、个人资料或未获授权的文献。备份时将报告、核验包和`outputs/records/evaluation_records.json`一起保存。
